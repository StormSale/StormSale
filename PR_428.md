## Description

Adds focused Vitest coverage for account-merge / closed-sequence detection and trustline balance synchronization requested in issue #428. Production code is not modified.

### Added — `src/tests/account-balance-sync.test.ts` (8 tests)

**Closed / merged account reaction**

- A Horizon `404` is surfaced as `0.0000000 (Unfunded)` by `fetchXlmBalance`; `fetchAssetBalances` returns zeroed XLM/USDC/EURC and `fetchStellarAccountDetails` returns `status: "unfunded"`, `exists: false`, `trustlineCount: 0`.
- `useAccountReserve` falls back to zero trustlines for a missing account and recovers to live trustline data after `refresh()` without remounting.
- Switching to the destination account discards an in-flight stale response from the merged source account (the `requestIdRef` guard).
- `Web3Context.connectWallet("readonly", destination)` updates `userAddress` and reloads both XLM and multi-asset balances for the new account inside the same mounted React tree.

**Trustline balance reload without a page refresh**

- Successive Horizon snapshots update USDC/EURC/XLM through `fetchAssetBalances`, and `Web3Context.refreshBalances()` updates the displayed `assetBalances` in place.
- A foreign-issuer USDC trustline is ignored in favour of the authentic Circle SAC issuer; an unknown `STORM` balance in the snapshot is ignored without corrupting USDC/EURC parsing.

The current codebase has no native `ACCOUNT_MERGE`/`SUB_ACCOUNT` operation and no `STORM` escrow asset (`EscrowAsset.code` is `XLM | USDC | EURC`). The tests therefore cover the observable data/UI signals that exist today (Horizon 404 → unfunded/fallback, account switching, issuer-filtered USDC/EURC reload) and pin the current handling of an unsupported `STORM` code.
