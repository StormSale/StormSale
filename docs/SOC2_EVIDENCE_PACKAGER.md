# Automated SOC 2 Type II Audit Evidence Packager with Hash Receipts

## 🛡️ Overview

The **Automated SOC 2 Type II Evidence Packager** allows enterprise compliance officers and external auditors to compile, cryptographically verify, and export an immutable evidence bundle covering the platform's security controls.

The generator binds:

1. **Live Smart Contract Controls & State Snapshots**: On-chain escrow parameters, client-side encryption configurations, access permissions, and Soroban persistent storage rules.
2. **Continuous Integration & Quality Gate Logs**: GitHub Actions workflows, secret scanning policies, branch integrity rules, and automated test summaries.
3. **Automated Test Run Receipts**: Execution results from all unit, integration, and end-to-end test suites.
4. **Deterministic Codebase & Evidence Hashes**: SHA-256 digests of all evidence and platform files bound into a canonical Merkle root digest.
5. **Verified Auditor Digital Signature**: Ed25519 cryptographic signature generated by an authorized platform auditor key (`Keypair`), packaged with public key certificates.

## 🔑 Environment Configuration

Add the platform auditor private key to your server or CI environment (or `.env` for local script execution):

```env
# Server/CI Platform Auditor Key for Automated SOC 2 Type II Evidence Packaging
# Ed25519 Secret Key (Stellar format S... or 64-char hex string)
AUDITOR_PRIVATE_KEY=<your-auditor-secret-seed>

# Optional client-side allowlist of trusted auditor public keys for in-browser verification
VITE_AUTHORIZED_AUDITOR_KEYS=<auditor-public-key-G...>
```

> **Important**: Never commit auditor private keys to version control or expose them in client bundles with `VITE_`. The packager will strictly throw an `AuditorSigningError` and refuse to produce an unsigned evidence pack if the key is missing or invalid.

### Generating a New Auditor Keypair

You can generate a cryptographically secure Ed25519 keypair at any time using the bundled utility:

```bash
node scripts/generate-auditor-key.mjs
```

This will output:

- **Public Key (Key ID)**: `G...` (recorded in `public-key.pem` and `signature.json`)
- **Secret Seed**: `S...` (to be set in `AUDITOR_PRIVATE_KEY`)

## 🚀 How to Export the Evidence Pack

### 1. From the Auditor Enterprise Portal UI

1. Connect your Stellar wallet and verify the **Auditor** role from the Dashboard or Auditor Portal.
2. Navigate to **Compliance Report** (or the **SOC 2 Evidence** tab).
3. Click **"Export SOC 2 Evidence Pack"**.
4. The application will collect contract state, aggregate test and CI logs, compute deterministic SHA-256 digests, sign the bundle with the auditor key, and download `soc2-evidence-pack-<timestamp>.zip`.
5. An immutable audit record is immediately appended to the **Audit History** console.

### 2. Programmatically via TypeScript API

```typescript
import { exportSoc2EvidencePackAction } from "./src/lib/auditor/exportService";

const result = await exportSoc2EvidencePackAction(
  {
    userAddress: "G...",
    userRole: "AUDITOR",
  },
  {
    auditorPrivateKey: process.env.AUDITOR_PRIVATE_KEY,
  },
);

console.log("Pack Root Digest:", result.rootDigest);
console.log("Signed by:", result.signature.keyId);
```

## 🔍 How an Auditor Verifies the Evidence Pack

### Method 1: In-Browser Verification Portal

1. Open the StormSale Auditor Enterprise Portal -> **Compliance Report**.
2. Scroll to the **Independent Pack Verification Suite**.
3. Drag and drop the downloaded ZIP archive into the dropzone.
4. The client re-computes all SHA-256 hashes, checks the Merkle root digest, validates every file against `hashes.json`, and verifies the Ed25519 digital signature against configured authorized auditor keys.

### Method 2: Standalone CLI Verification Script

Compliance reviewers can verify any pack without running the web server by supplying the expected auditor public key:

```bash
node scripts/verify-evidence-pack.mjs path/to/soc2-evidence-pack-<date>.zip <expected-auditor-public-key>
```

### Method 3: Standard OpenSSL Verification

Auditors can inspect and verify the pack using standard OpenSSL CLI:

```bash
# 1. Unzip the pack
unzip soc2-evidence-pack-*.zip -d extracted-pack
cd extracted-pack/*

# 2. Verify all file hashes against hashes.json
sha256sum -c <(jq -r '.files | to_entries[] | "\(.value)  \(.key)"' hashes.json)

# 3. Verify the Ed25519 digital signature against rootDigest
openssl pkeyutl -verify -pubin -inkey public-key.pem \
  -sigfile <(xxd -r -p <(jq -r .signatureHex signature.json)) \
  -in <(jq -j .signedRootDigest signature.json)
```
